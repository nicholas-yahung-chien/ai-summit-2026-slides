# 7 分鐘 IBM Bob 示範腳本

狀態：素材與參考實作已備妥；尚未在 IBM Bob 登入環境實際排演。不可用參考實作冒充 Bob 的產出。

## 事前

1. 建立獨立示範資料夾，只複製 demo/README.md、registration.mjs、registration.test.mjs、acceptance.mjs；不要把 reference/ 給代理。
2. 確認 Bob 可用、Node 已安裝、字體放大。用合成 ID，沒有憑證或個資。
3. 執行 `node --test registration.test.mjs` 確認起點存在失敗案例；這是預期狀態。
4. 備援另外開啟 reference/，清楚標示「預先準備」。預先記錄可實際取得的 Bobcoin/使用量欄位，不猜測 token。

## 現場提示詞

**0:00–1:00 理解**

「請讀 README.md 與驗收案例，用中文說明需要實現的行為、邊界與不在範圍的項目。先不要修改檔案。請指出規格是否有矛盾。」

**1:00–2:00 計畫**

「提出最小實作計畫，說明重複報名與額滿檢查的優先順序，以及如何避免修改原陣列。不要為這個小任務建立不必要的代理編排。」

**2:00–5:00 執行**

「依確認的規格完成 registration.mjs。執行 node --test registration.test.mjs，若失敗就分析原因並修正。不要降低或刪除驗收條件來讓測試通過。」

**5:00–7:00 驗收**

「把需求逐項對照程式與測試結果，列出已驗證、未驗證和部署前還缺少的項目。摘要這次變更，不要把尚未執行的檢查說成通過。」

看測試結果、diff 與風險邊界。最後把重複使用的規則保存為團隊的文件或技能，示範從單次工作到組織記憶的閉環。

## 中斷時

60 秒內排除連線問題；超過就切至簡報第 19 頁。執行 `node --test demo/reference/registration.test.mjs` 展示預備參考版本，明確說明不是現場模型輸出。
